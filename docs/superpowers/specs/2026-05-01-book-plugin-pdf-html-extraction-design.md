# Book Plugin PDF HTML Extraction Design

Date: 2026-05-01
Status: Approved for planning

## Goal

Replace mocked HTML generation in `BookPlugin::FlashCardsController` with real HTML generated by `extract2.py`, while preserving cached `BookHtml` behavior.

## Scope

- Keep flash-card flow and models as-is.
- Replace only the extraction behavior used by `find_or_create_book_html`.
- Reuse cached `BookHtml` records when they already exist.
- Do not add background jobs or refresh UI in this change.

## Decisions

1. Use a service object approach (`BookPlugin::PdfHtmlExtractor`).
2. Keep UI and DB `page_number` as 1-based.
3. Convert to zero-based only at Python call boundary (`page_number - 1`).
4. On extraction failure, show alert and do not create `BookHtml`.

## Architecture

### Controller

`BookPlugin::FlashCardsController` remains orchestration-focused:

- Parse incoming `page_number`.
- Call `find_or_create_book_html(page_number)`.
- On success, continue existing new/create flow.
- On extractor failure, set `flash.now[:alert]`, keep form usable, and render `new` with `unprocessable_entity`.

### Service

Create `BookPlugin::PdfHtmlExtractor` with one responsibility: execute Python extraction and return structured result.

Input:

- `pdf_path` (from attached book file on disk)
- `page_number` (1-based)

Output:

- `success?` boolean
- `html` (on success)
- `error_message` (on failure)
- optional debugging metadata for logs (`exit_code`, `stderr`)

## Command Contract

Service executes command equivalent to:

`python3 extract2.py <pdf_path> --page <page_number-1> --out <tmp_html_path>`

Notes:

- Keep script defaults for `--scale` and `--output-dir` for now.
- Use temporary output file for `--out`, then read content.
- Treat empty output file as failure.
- Capture non-zero exits and timeout as failure.

## Data Flow

1. User opens flash-card form with `page_number`.
2. Controller calls `find_or_create_book_html(page_number)`.
3. If `BookHtml` exists for `book + page_number`, return cached row (no script call).
4. If missing:
   - Service runs Python extraction.
   - On success, create `BookHtml` with extracted HTML.
   - On failure, do not persist `BookHtml`, show alert.

## Error Handling

Failure conditions:

- Python executable missing
- script returns non-zero exit code
- timeout during execution
- output file missing or empty
- unreadable PDF path

User-facing behavior:

- Show: "Could not extract page HTML. Please try again."
- Return status `422 Unprocessable Entity`
- Keep user on flash-card `new` page
- No fallback to mock HTML

Developer-facing behavior:

- Log detailed extraction failure context in Rails logs.

## Testing Strategy

### Service tests

- Success: returns parsed HTML from generated output file.
- Non-zero exit: returns failure with error message.
- Timeout: returns failure.
- Empty output: returns failure.

### Controller tests

- Cache miss: extractor success creates `BookHtml` and renders preview.
- Cache hit: does not invoke extractor; uses existing HTML.
- Extractor failure: no `BookHtml` created, alert rendered, status 422.

## Non-Goals

- Async extraction / background jobs
- Manual refresh/re-extract action
- Changes to flash-card JSON payload format

## Rollout Notes

- This change is backward-compatible with current flash-card create flow.
- Existing cached `BookHtml` rows continue to work unchanged.
